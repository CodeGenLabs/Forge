# ARCHITECTURE.md — Forge システムアーキテクチャ

## 1. システムの分類

Forgeは、Gitリポジトリ内で直接動作する**個人用ソフトウェアエンジニアリングハーネス**です。

### 主要な特徴:
- **常駐サービスゼロ:** 短命なCLIコマンド呼び出しのみで完結。
- **Gitがデータベース:** すべての状態、クレーム、スキーマ、検証レポートはGitにコミットされるプレーンテキスト。
- **コア内LLM呼び出しゼロ:** カーネルは100%決定論的であり、推論は外部のホストエージェントが担う。
- **多言語対応:** Python, TypeScript, Go, C# (.NET) をサポート。非対応言語でも決定論的ハッシュへ安全にフォールバック。

---

## 2. コアモジュール構成

### 2.1 カーネルモジュール
1. `fingerprint`: Tree-Sitter ASTハッシュ化、シンボル検索、行正規化。
2. `derive`: 機械的コード解析 (`inventory`, `deps`, `tests`, `trace`, `backrefs`)。
3. `store`: クレームストアの解析と18項目の構造的整合性検証 (S1〜S18)。
4. `lifecycle`: 成果物DAGの解決、変更履歴管理、仕様デルタの統合。
5. `gates`: 不正な遷移をブロックする特定時点でのライフサイクルゲート。
6. `verify`: 自動テスト実行を含む11項目の客観的検証条件の照合。

---

## 3. 7つのAIスキル（推論層）

- `forge` (understand): トラック分類 (A/B/C) と変更の初期化。
- `investigate`: 既存コードの調査と候補クレームの立案。
- `specify`: 振る舞い要件と検証シナリオの定義。
- `plan-tasks`: 仕様に基づくTDDタスクの分解と順序付け。
- `implement`: Red-Green-Refactor に基づく厳格なテスト駆動実装。
- `curate-knowledge`: 承認済みクレームの更新とドリフト台帳の決済。
- `bootstrap`: 既存リポジトリへの3パス導入プロセスの先導。
